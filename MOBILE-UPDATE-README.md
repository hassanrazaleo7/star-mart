# Star Mart — mobile website + easy product entry

This update is based on your uploaded `star-mart-main(2).zip`, not the Expo app. Existing brand, categories, backend schema, checkout, owner/vendor/staff rights and accounting rules are preserved.

## What changed

- Phone storefront: compact menu, two-column product cards, bottom Home / Categories / Cart / Account bar, rounded category row, readable inputs, product/checkout dialogs and info/account pages fitted to small screens.
- Admin: drawer backdrop, readable/wrapping controls, responsive forms and contained horizontal table scrolling.
- Vendor: phone menu drawer with visible sign-out, photo upload and simple product form.
- One shared product form: image upload, name, category, purchase/supply price, selling price, stock, and owner supplier selection. Barcode camera/manual input, brand, pack size, unit and operational details are collapsed into More details. SKU is generated by backend.
- Save & add another keeps the category (and owner's supplier selection), clears the entered product/photo, and confirms success. Standard save closes the form and the owner list offers Add another product.
- Image upload failure keeps the saved product ID: retry updates the product and image instead of creating a duplicate.
- Stock inputs accept whole units. Vendor available stock remains supplier stock; only owner received stock is available for customer sales. Stocked vendor product restrictions and owner price approval remain backend-enforced.

## IMPORTANT: removed unrelated remote-code loader

The uploaded archive contained an obfuscated downloader/executor in root `api.js` and appended to `vite.config.js`. `package.json` ran `node api.js` before dev/start/build. These are unrelated to the grocery software. They were inspected as text, never executed here, and removed from the updated project.

3. If you ran the old website ZIP, run a full Windows Defender scan. Reset the exposed Neon/database password, update DATABASE_URL in local/Vercel settings and redeploy. Removal from this project is not a guarantee that a previously used computer has been cleaned.

## Local computer check

Extract the full project ZIP, open the folder containing package.json in VS Code, retain/create `.env.local` with your DATABASE_URL, then:

```bash
npm install
npm run dev
```

For phone browser on the same Wi-Fi:

```bash
npm run dev -- --host
```

Open the printed Network URL from the phone. Windows Firewall must permit Node on Private networks. The API stays loopback and is accessed through the Vite /api proxy. Barcode camera needs HTTPS (live Vercel) or localhost; local plain-HTTP LAN can use manual barcode entry or a USB keyboard scanner on the computer.

Your Neon URL must never be uploaded to GitHub. Testing with production DATABASE_URL writes to real store records; use a test branch for trial products/orders.

## How the owner adds a product

/admin → Products & stock → Add product → Add product photo → name/category/prices/whole stock → select supplier if applicable → Save or Save & add another. Use More details for a barcode, brand, pack size or notes.

## How the vendor adds a product

/vendor → Add product → photo/name/category/supply price/selling price/whole supplier stock → Save or Save & add another. Owner records actual stock received. Vendor cannot delete products or directly change mart stock.
